# 合规与硬规则

这些规则不是风格建议，而是这个技能存在的前提：采购结论会被用来花钱，错误的价格或售后承诺会造成实际损失。

## 数据真实性

**不得编造**以下任何一项：

- 价格、优惠券、满减、运费、税费
- 库存、发货时间、可采购数量
- 保修年限、保修范围、发票类型与税率
- 商品规格、型号、材质、产地
- 店铺资质、自营/旗舰店身份
- 销量、评价数、好评率

缺失就写 `UNKNOWN`。在 Markdown 报告里，"未知"比一个看起来合理的数字更有价值，因为它会触发人工确认。

### 价格特殊规则

- 价格缺失、空字符串、`null`、`0`、负数、"面议"、"登录后可见" → `price = null`，`price_status` 为 `hidden` 或 `unknown`
- `0` 几乎总是占位符，不是免费
- 列表页价格带（如 "¥4999–5999"）取到的数字必须标注为"起价"，不能当唯一价格
- **同一链接的不同配置价格必须分别记录**；不允许用一个价格代表整条链接
- 搜索页价与商品页价冲突时，以选中配置后的商品页价格为准，两条都进 `price_observations`

### 文本证据

每条价格/规格/评价必须带：

```json
{"field": "detail.warranty", "value": "3年上门保修", "source_url": "...", "snippet": "保修：3年上门保修", "confidence": 0.55}
```

`snippet` 是从页面上摘下的原话。没有 snippet 的"证据"只是模型的记忆，不能进报告。

## 平台边界

- 只覆盖淘宝、京东
- **拼多多明确排除**：不做爬虫/反爬替代
- 不在报告中出现"我们也看了拼多多"之类的表述，除非用户自己提供了数据
- 不接入未经授权的第三方比价 API

## 浏览器边界

浏览器用于**读取页面与点选配置**，不用于绕过限制：

- 遇到登录墙 → 停止，让用户在浏览器窗口手动登录
- 遇到验证码/滑块/人机验证 → 停止，不自动点击、不使用打码服务
- 遇到 403/访问受限/页面提示"暂时无法展示该商品的信息" → 停止，记录状态
- 不修改 UA 伪装、不注入反检测脚本、不导出 Cookie
- 同一平台严格串行，页面之间间隔 3–5 秒

## 反爬与工具边界

- 不自建淘宝/京东爬虫
- 不复刻 TLS 指纹、不逆向签名算法
- 不把 Cookie 写入日志、报告或代码仓库
- 不把 playwright-mcp 的登录态导出给其他程序

## 记录与可追溯

一份可审计的采购报告至少保留：

- 生成时间、简报原文、评分卡全文
- 每个**配置**的来源 URL、采集时间、价格状态、`option_path`
- 每条证据的 URL + snippet + confidence
- 评价的样本量、评分、评价数与负评主题原话
- 被淘汰候选的淘汰原因（含实际值与阈值）
- 所有 warnings 与 errors（包括页面状态与中断原因）

这些都在 `report.json` 里。Markdown 是给人看的摘要，JSON 才是审计凭证。

## 建议性语言

报告给的是**建议**，不是承诺：

- 用"建议""候选""需复核"，不用"保证最低价""一定可开票"
- 价格结论必须带"以结算页为准"
- 库存结论必须带"下单前确认"
- 拆单节省必须带 `savings_status`

## 隐私

- 报告里不包含用户账号、收货地址、手机号
- 浏览器 profile 目录不放进项目仓库
- `.gitignore` 必须覆盖 `evidence/`、`output/`、浏览器 profile、日志

## 自检清单（交付前逐条确认）

- [ ] 需求与评比维度已由用户确认并冻结（`confirmed.by_user`）
- [ ] 推荐候选的 `fit_score` 不低于阈值，且未满足项已列出
- [ ] 同价位比较基于 `value_score`，不是加权总分
- [ ] `risk` 维度没有参与主排序
- [ ] 没有把缺失价格写成 0 或具体数字
- [ ] 没有编造券/运费/税/库存/保修/发票
- [ ] 价格结论带"以结算页为准"
- [ ] 隐藏价格候选未参与价格排序
- [ ] 拼多多未出现在结果中（或已明确说明排除）
- [ ] 每个候选都是**一个配置**，`option_path` 非空且与价格对应
- [ ] 同一链接的不同配置没有被合并成一个价格
- [ ] 同一链接下满足条件的多个配置都保留为候选
- [ ] 命中排除项的 listing 已早停（`aborted`）且未参与评分
- [ ] 推荐位/搭配购没有进入候选池
- [ ] 已滚动页面，参数/评价/售后不是只取了首屏
- [ ] 低于官方/自营锚点 70% 的候选已标记 ⚠ 且价格分封顶，未被当作正常低价
- [ ] 浏览器遇到登录/验证码/内容未返回时已停止并提示
- [ ] 每条证据有 source_url + snippet
- [ ] 评价样本量已记录，未用"口碑好/差"替代样本
- [ ] 评分卡权重和为 1，缺失策略已声明
- [ ] 报告含 warnings/errors 与淘汰原因
- [ ] Markdown/CSV/JSON 三份产物都已生成
