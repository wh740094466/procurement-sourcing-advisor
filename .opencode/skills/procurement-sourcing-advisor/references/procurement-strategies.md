# 采购策略（Stage 6–8）

## 价格不是到手价

采集到的 `price` 是**选中该配置后**商品页显示的价格。它通常**不含**：

- 账号券、店铺券、跨店满减、支付优惠
- 运费（尤其大件、偏远地区）
- 税费（企业采购的专票/普票差异）
- 安装、延保、以旧换新

`scripts/landed_price.py` 因此输出三档：

| status | 含义 | 报告写法 |
|---|---|---|
| `exact` | 所有费用项显式提供 | "到手价 ¥X（已含运费/税/券，仍以结算页为准）" |
| `partial` | 只有商品价，其余未知 | "商品价 ¥X 起；到手价下限 ¥X，缺运费/税/券" |
| `unknown` | 价格缺失/隐藏 | "价格未知，不参与价格比较" |

`floor` 是**已知部分之和**，不是"最终价"。`ceiling` 只在运费、税、其他费用都已知、仅券未知时才给出（券按 0 处理）。缺少运费时不要给上限——那等于假设包邮。

### 税费

`tax_rate` 单独出现是**有歧义的**：中国电商标价通常已含增值税。脚本要求同时提供 `price_includes_tax`（或 `tax_included`）才计算税费，否则把 tax 记为缺失。不要因为"企业要专票"就默认加 13%。

## 同款不同价：先分档，再比价

电商价格不是单一透明价。同一个型号通常同时存在四档货：

| 档位 | 特征 | 能否直接比价 |
|---|---|---|
| 官方自营 / 官方旗舰 | 正品行货带票、厂保或自营售后 | 作为**锚点** |
| 第三方全新带票 | 有发票、店保，货源不明 | 可比，但要验证 |
| 官换 / 店保 | 标题常写"全新官换""店保 N 年" | 另一档，不能按新品价比较 |
| 散装 / 拆机 / 成色不明 | 无发票、无厂保、价格显著低 | 只能作为"待核实" |

流水线用同型号自营/官方旗舰价格的中位数做锚点；低于锚点 70% 的候选，价格分封顶为最低档，并标记 ⚠。要解除封顶，必须同时满足：页面写明"全新/原封" + 可开发票 + 保修主体明确。

这条规则的目的不是"认定低价是假货"，而是**避免把不同成色的商品放在同一个价格维度上排序**。

## TCO 不是"价格 × 年限"

TCO 的组成：

```
购买价 + (耗材/年 + 能耗/年 + 维护/年) × 年限 + 配件 - 残值 + 停机成本
```

`scripts/tco_calc.py` 对每一项独立判定已知/未知：

- 任一年度费用未知 → TCO 只能是下限，`status = partial`
- 只有残值未知 → 可以把残值按 0 给出上限（保守）
- 购买价未知 → `status = unknown`，不计算

**不要**为了让 TCO 看起来完整而填 0。填 0 等于断言"没有耗材成本"，这是编造。

## 拆单 / 凑单

拆单只有在以下条件同时满足时才值得比较：

1. 数量 > 1
2. 简报允许拆单
3. 至少两个候选**评分接近**（默认不低于最高分的 90%）
4. 库存/可采购数量可知

第 3 条是 `bundle_optimizer.py` 的 `min_score_ratio`。没有它，优化器会为了省几十块钱推荐一个评分低 20 分的店铺，这是典型的"省小钱赔大钱"。

比较口径：

- 单渠道：排名第一的候选吃下全部数量
- 拆单：在合格池内按单价从低到高分配，受 `max_orders` 和每候选可采购数量限制

输出必须说明 `savings_status`：

- `exact`：两边都是完整费用，差额可信
- `floor_comparison`：只比较了下限；运费/券/库存未完全确认时，**不能**断言"拆单更省"

库存未知时脚本会加 `stock_assumed` 警告。下单前必须确认可采购数量，否则拆单方案可能根本下不了单。

## 渠道与风险

- 京东自营、品牌官方旗舰店：售后责任清晰，优先级高
- 第三方专营/专卖店：价格可能更低，但退换货与发票风险上升
- 淘宝个人店/高销量C店：需要额外证据（企业资质、开票承诺、保修条款）
- 广告位（`flags.ad = true`）：直接淘汰，它不是自然排序结果

销量不是质量证据。它能提示"这家店可能有履约能力"，但不能替代保修条款和发票承诺。不要把销量写进评分卡的"质量"维度。

## 何时停止检索

继续翻页的边际收益很快归零。建议：

- 每个平台先跑 2–3 组关键词，每组看前 20–30 条
- 若连续两组关键词没有出现新的高分候选，停止
- 候选池达到 30–50 条后，优先做**详情补全**而不是继续扩大召回
- 详情补全只针对有希望进入前 5 的候选

## 当所有候选都被淘汰

这是合法结果，不要为了"给个推荐"而放宽硬条件。正确做法：

1. 报告"无合格候选"，列出淘汰原因分布（超预算 X 条、二手 Y 条、无发票 Z 条）
2. 指出最可能放宽的一项，并说明放宽的后果
3. 建议用户确认预算或规格后再跑

## 当价格全部缺失

淘宝部分类目会隐藏价格（登录后可见/面议），京东个别商品价格区不渲染。这时：

1. 标记 `price_status = hidden`，**不参与**价格排序
2. 若关键候选 ≤ 5 个，重新点选配置并读取价格；登录后可见的先让用户登录
3. 仍失败 → 报告"价格不可比"，只按规格/售后给建议，不给价格排序

永远不要用 0、1 元、"起"字后面的数字，或同链接其他配置的价格当确定价格。
